# Сборка установщика PumpTestApp - инструкция

## Требуемая структура папок

Все файлы сборки должны занять СТРОГО такие места относительно корня
проекта (там же, где сейчас лежит папка `src`):

```
PumpTestApp/                        <- корень проекта (где сейчас src)
│
├── run.py                          <- прислан отдельно, положить сюда
├── PumpTestApp.spec                <- прислан отдельно, положить сюда
├── gur_pump_icon.ico                <- иконка программы, положить сюда
│
├── src/                            <- уже существует, не трогать
│   ├── version.py
│   ├── resources/
│   └── ...
│
├── installer/                      <- НОВАЯ папка, создать
│   ├── installer.iss               <- прислан отдельно, положить сюда
│   ├── build_installer.py          <- прислан отдельно, положить сюда
│   └── prefilled_data/             <- НОВАЯ подпапка, создать
│       └── pumps.db                <- сюда положить готовую, наполненную
│                                       реальными данными базу (ту, что
│                                       делали через populate_real_data.py)
│
└── .venv/                          <- уже существует
```

После первой успешной сборки в `installer/` дополнительно появятся:
- `build_config.iss` - создаётся автоматически (версия, организация, основной пароль), не редактировать вручную
- `output/PumpTestApp_Setup_v<версия>.exe` - готовый установщик

И в корне проекта появится:
- `dist/PumpTestApp/` - результат работы PyInstaller (промежуточный,
  именно эту папку упаковывает установщик)
- `build/` - служебная папка PyInstaller, можно игнорировать/удалять

## Что нужно установить один раз, перед первой сборкой

1. **PyInstaller** - в то же виртуальное окружение, где уже стоят PyQt5
   и остальные библиотеки:
   ```
   .venv\Scripts\python.exe -m pip install pyinstaller --break-system-packages
   ```

2. **Inno Setup** - скачать и установить отдельно, с официального сайта:
   https://jrsoftware.org/isdl.php (файл `innosetup-6.x.x.exe`, обычная,
   стандартная установка). Путь к `ISCC.exe` ищется автоматически по
   нескольким типичным местам установки (см. `find_iscc()` в начале
   `build_installer.py`) - вручную ничего указывать обычно не нужно,
   если Inno Setup стоит в одном из этих мест.

## Сама сборка - одна команда

Из корня проекта:
```
.venv\Scripts\python.exe installer\build_installer.py
```

Сначала скрипт спросит два значения прямо в консоли:
- **Основной пароль программы** - будет одинаковым на всех копиях этого
  релиза, записывается прямо в `src/auth.py`. Если пароль уже был
  задан раньше - его текущее значение показывается как вариант "оставить
  как есть" (просто нажмите Enter, не вводя ничего).
- **Название организации** - показывается пользователю на экране
  установки (по умолчанию "NAMI", если ничего не ввести).
```

Скрипт сам, по порядку: подставит текущую версию из `version.py`,
запустит PyInstaller (может занять несколько минут - следит за
консолью, там будет прогресс), затем соберёт сам установщик через
Inno Setup. Готовый файл появится в `installer\output\`.

## Что стоит проверить после самой первой сборки

Сборка почти наверняка потребует одной-двух итераций, прежде чем
заработает идеально - это нормально для PyInstaller, заранее
гарантировать полный список всех технических деталей без реальной
сборки на вашей машине невозможно. В первую очередь стоит проверить:

1. **Запускается ли собранная программа вообще** - `dist\PumpTestApp\PumpTestApp.exe`,
   ещё до того, как упаковывать в установщик. Если появится
   `ModuleNotFoundError` на что-то из pandas/openpyxl/matplotlib - нужно
   будет добавить недостающее имя модуля в список `hiddenimports`
   внутри `PumpTestApp.spec` (в файле есть примечание об этом) и
   пересобрать.

2. **Открываются ли иконки, шрифт, инструкция** внутри собранной
   программы - если что-то не отображается, скорее всего, дело в пути
   (см. `app_paths.py` - но раз мы его уже подготовили заранее, это
   маловероятно).

3. **После установки на "чистой" виртуальной машине** (без Python,
   без ранее установленных библиотек) - работает ли программа так же,
   как на компьютере разработки. Это самая важная финальная проверка.

4. **Экраны установщика** - основной пароль (для доступа к настройке
   резервного), резервный пароль и сетевой путь - при реальном запуске
   установщика убедитесь, что: неверный основной пароль не пускает
   дальше (показывает ошибку), пустой основной пароль тихо пропускает
   экран резервного пароля, а сетевой путь показывается предзаполненным
   текстом (значением `DefaultNetworkPath`, если задавали). После
   установки в реестре (`regedit`,
   `HKEY_CURRENT_USER\Software\PumpTestApp\MainSettings`) должны быть
   видны правильные значения, если сетевой путь заполняли.

## Известные ограничения этой версии

- Собирается только вариант **с папкой** (`--onedir`) - вариант с одним
  файлом (`--onefile`) обсуждали, но договорились начать с более
  простого варианта
- Основной пароль теперь запрашивается интерактивно при каждом запуске
  `build_installer.py` и записывается в `src/auth.py` автоматически -
  отдельного экрана для него в САМОМ УСТАНОВЩИКЕ нет (так и
  договаривались - он один и тот же на всех копиях), но экран проверки
  доступа к резервному паролю сверяется именно с этим значением
- Список путей поиска `ISCC.exe` в `find_iscc()` (внутри
  `build_installer.py`) может потребовать дополнения, если Inno Setup
  установлен в нестандартное место
- Поле сетевого пути показывает обычный предзаполненный текст (значение
  `DefaultNetworkPath`), а не серую подсказку-placeholder - пробовали
  реализовать через свойство `TextHint`, но конкретная установленная
  версия Inno Setup его не поддержала (`Unknown identifier 'TEXTHINT'`
  при компиляции), поэтому вернулись к более простому и надёжному
  варианту. Если поле не нужно - значение достаточно стереть вручную
  перед тем, как нажать "Далее"
