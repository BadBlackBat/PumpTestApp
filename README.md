Итоговый список и порядок

Вот как я бы расставил приоритеты, с обоснованием после каждого пункта:

1. Защита от одновременного редактирования одной записи
Это последний серьёзный функциональный пробел в самой логике данных — разумно закрыть его до того, как начнётся реальная многопользовательская эксплуатация, а не после.

2. Расширенные точки модификации (Excel + автораспознавание)
Независимая, самодостаточная задача — не блокирует и не блокируется ничем другим, можно сделать в любой момент. Ставлю пораньше, пока ещё идёт активная разработка, а не когда всё уже «заморожено» перед релизом.

3. Пароль (хранение в коде + резервный локальный файл с хешем)
Тоже независимая, некрупная задача.

4. Номер версии в настройках
Мелочь, но логически имеет смысл сделать ближе к моменту, когда версия 1.0 действительно оформится как таковая — то есть после основных функциональных доработок (1-3), а не в самом начале.

5. Реальная проверка с несколькими одновременно работающими людьми
Теперь, когда функциональность (включая защиту записи) уже готова — самое время устроить настоящую проверку, а не тестировать дальше в одиночку. Если вскроются нюансы — лучше сейчас, чем после того, как программа уже официально «в работе».

6. Сборка установщика
После того как код стабилизировался и прошёл проверку — самое время упаковать. Собирать установщик раньше, пока код ещё активно меняется, означало бы пересобирать его при каждой мелкой правке, что просто лишняя трата времени.

7. Наполнение базы реальными данными (через скрипт)
Ближе к самому запуску в реальную работу — присылай формат JSON, когда будет готов, адаптирую под наполнение отдельным разовым скриптом, как договорились.

8. Описание и инструкция по программе
Последним шагом — чтобы описывать то, что уже точно не будет меняться, а не переписывать инструкцию по нескольку раз вслед за доработками.

9. Редактирование истории сделать через пароль
